# Контроль дорожной разметки

Учебный проект по курсу «Fullstack».

Приложение для дорожной службы, которая следит за состоянием разметки на улицах города.
Инспектор загружает фотографии участков, на снимках отмечаются дефекты разметки
(стёртые линии и пробелы), а по найденным дефектам диспетчер формирует задания на ремонт.

Текущий этап — лабораторная работа №1: интерфейс и каркас frontend. Данные на этом этапе
демонстрационные, серверная часть появится в следующих работах.

## Пользовательские сценарии

1. Инспектор загружает фотографию участка улицы и указывает адрес и дату съёмки.
2. Загруженный снимок попадает в общий список, где видно его статус обработки.
3. Диспетчер открывает реестр дефектов, фильтрует его по типу и серьёзности.
4. По выбранному дефекту диспетчер создаёт задание на ремонт с исполнителем и сроком.
5. Диспетчер отслеживает статусы заданий на ремонт.

## Экраны

| Экран | Маршрут | Назначение |
| --- | --- | --- |
| Загрузки | `/uploads` | Список загруженных снимков: адрес, дата, статус обработки, число дефектов |
| Новая загрузка | `/uploads/new` | Форма добавления снимка участка |
| Дефекты | `/defects` | Реестр найденных дефектов с фильтрами по типу и серьёзности |
| Задания | `/tasks` | Задания на ремонт: исполнитель, срок, статус |

Корневой адрес `/` перенаправляет на `/uploads`. Несуществующие адреса открывают
страницу «Страница не найдена».

## Стек

- React + TypeScript
- Vite — сборка и dev-сервер
- Mantine — библиотека UI-компонентов
- React Router — клиентская маршрутизация

## Структура проекта

```
public/photos/        демонстрационные снимки участков
src/
  components/         общие компоненты интерфейса (макет, бейдж статуса)
  pages/              экраны приложения, по файлу на маршрут
  data/               демонстрационные данные и подписи статусов
  utils/              вспомогательные функции форматирования
  types.ts            типы предметной области
  theme.ts            настройки оформления Mantine
  App.tsx             описание маршрутов
  main.tsx            точка входа, подключение провайдеров
docs/screenshots/     скриншоты экранов
```

Экраны отделены от общих компонентов, данные предметной области и их типы вынесены
из компонентов в отдельные модули.

## Модель данных

Три сущности, связанные по идентификаторам:

- `Upload` — загруженный снимок участка;
- `Defect` — дефект разметки, найденный на снимке (`uploadId` ссылается на `Upload`);
- `RepairTask` — задание на ремонт по конкретному дефекту (`defectId` ссылается на `Defect`).

Адрес хранится только у снимка, дефект и задание получают его по цепочке ссылок.


## Запуск frontend

Нужен Node.js версии 20 или новее.

```bash
npm install
npm run dev
```

Приложение открывается на http://localhost:5173

Остальные команды:

```bash
npm run build     # сборка в папку dist
npm run preview   # посмотреть собранную версию
```
